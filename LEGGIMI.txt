Linea del tempo - Guerre di religione in Europa
================================================

Applicazione Next.js esportata staticamente e pubblicata su GitHub Pages:
https://croccantino.github.io/lineadeltempo/

I dati della linea del tempo sono in Firebase Realtime Database; le immagini
caricate dall'editor vengono scritte in RTDB e poi copiate automaticamente nel
repository pubblico.

SVILUPPO LOCALE
---------------
npm install
cp .env.local.example .env.local
# inserisci in .env.local i valori del progetto Firebase
npm run dev

Apri http://localhost:3000 per la linea del tempo e
http://localhost:3000/modifica per l'editor.

BUILD STATICO
-------------
npm run build

L'output viene creato in out/. In locale il basePath è vuoto.
Per simulare GitHub Pages:
NEXT_PUBLIC_BASE_PATH=/lineadeltempo npm run build

VARIABILI D'AMBIENTE
--------------------
NEXT_PUBLIC_FIREBASE_*  configurazione web Firebase (incorporata nel build)
NEXT_PUBLIC_BASE_PATH   /lineadeltempo per GitHub Pages, vuoto in locale
FIREBASE_DATABASE_URL   URL RTDB per lo script di sincronizzazione

La workflow Pages legge le variabili NEXT_PUBLIC_FIREBASE_* dalle Repository
variables di GitHub. Il secret FIREBASE_DATABASE_URL è usato dalla workflow di
sincronizzazione immagini.

DATI
----
timeline/main   righe (con colore per paese), eventi e updatedAt
images/<uuid>   { data: "data:image/...;base64,...", type, size, createdAt }

Il colore delle chip dipende dal paese (TimelineRow.col). Nell'editor il
pulsante "Rimescola colori" ridistribuisce casualmente i colori tra i paesi.

L'editor salva l'evento con img = "rtdb:<uuid>". La GitHub Action converte
l'immagine in WebP e aggiorna l'evento a img = "/images/<hash>.webp".

UPLOAD
------
L'editor comprime l'immagine nel browser (max 2 MB) e la scrive direttamente
nel nodo images/<uuid> di RTDB tramite Firebase SDK. Non ci sono API server né
Firebase Storage.

SINCRONIZZAZIONE AUTOMATICA
---------------------------
La workflow .github/workflows/sync-images.yml parte ogni 10 minuti e può essere
avviata manualmente da GitHub (Actions -> Sincronizza immagini -> Run workflow).

Esegue scripts/sync-images.mjs --commit --apply:
- legge timeline/main;
- converte le immagini rtdb: in WebP 1200 px dentro public/images;
- committa e pusha solo public/images;
- aggiorna gli eventi da rtdb:<uuid> a /images/<hash>.webp;
- elimina i nodi images non più referenziati dopo 7 giorni.

Il repository deve essere pubblico perché le GitHub Actions gratuite siano
illimitate. La workflow ha bisogno del secret FIREBASE_DATABASE_URL (facoltativo
se si usa l'URL predefinito nello script).

Per provare la sincronizzazione in locale:
npm run sync-images

DEPLOY GITHUB PAGES
-------------------
La workflow .github/workflows/deploy-pages.yml compila l'app e pubblica out/ a
ogni push su main. In Settings -> Pages -> Build and deployment -> Source va
selezionato "GitHub Actions".

Il basePath /lineadeltempo è impostato nella workflow. I percorsi delle immagini
locali vengono prefissati a runtime con lo stesso basePath.

AUTENTICAZIONE
--------------
Login e Signup usano Firebase Authentication (email/password). Per attivarli:

1. Console Firebase -> Authentication -> Sign-in method.
2. Abilita il provider "Email/Password".
3. In Authentication -> Settings -> Authorized domains verifica localhost e
   aggiungi il dominio GitHub Pages (es. croccantino.github.io).

Non servono nuove variabili: viene usata NEXT_PUBLIC_FIREBASE_AUTH_DOMAIN.
L'editor /modifica è protetto lato client: senza sessione mostra una schermata
di accesso e rimanda al login nella pagina principale.

La protezione di /modifica è solo un filtro di interfaccia: le regole RTDB
restano aperte, quindi chi conosce l'URL del database può ancora scrivere
direttamente. Per una sicurezza reale vanno aggiunte regole RTDB con auth e va
adattato scripts/sync-images.mjs, che oggi usa REST anonimo.

REGOLE FIREBASE
---------------
database.rules.json è attualmente aperto in lettura e scrittura su timeline/main
e images. È una configurazione temporanea: prima di rendere l'editor pubblico
va aggiunta l'autenticazione e vanno ristrette le regole di scrittura.

Le vecchie regole Firestore/Storage e i file statici (index.html, app.js,
style.css) non sono più usati.

LIMITI
------
- Limite applicativo immagini: 2 MB.
- RTDB free: 1 GB di spazio e 10 GB/mese di download.
- Dopo il push della Action, Pages deve completare il deploy: per pochi istanti
  il nuovo /images/<hash>.webp può restituire 404.
- GitHub disattiva le workflow programmate dopo 60 giorni senza attività del
  repository: se succede, riattivale dalla pagina Actions.

COMMIT
------
Le workflow creano commit automatici con prefisso
"chore(images): sincronizza immagini da Firebase".
